# 항공권·자유여행 특가 알리미

싸게 나온 항공권과 여행사 자유여행 상품을 찾아 텔레그램으로 알려준다.
어디서 사는지 링크도 같이 보낸다.

## 무엇을 걸러 주나

**여행 기간을 거리로 정한다.** 인천에서 4,500km 안쪽(일본·동남아·대만 등)은
2~4일 왕복만, 그 바깥(미주·유럽·호주 등)은 7~14일 왕복만 본다.
짧게 다녀올 수 없는 곳의 3일 일정은 아예 후보에서 뺀다.

**싸다는 건 그 노선의 평소 가격과 비교해서 정한다.** 절대 금액이 아니다.
기준선을 두 개 쓰고, 둘 중 하나만 걸려도 알린다.

| 기준 | 무엇을 잡나 |
|---|---|
| 평소 가격(중앙값) 대비 **-25%** | 비싼 날짜들 사이에 끼어 있는 싼 날 |
| 최근 7일 **최저가** 대비 **-20%** | 노선 전체가 갑자기 떨어진 순간 |

두 번째는 스카이스캐너 Drops와 같은 방식이다. Drops는 앱 전용이라 가져올 API가
없어서 규칙만 옮겨 왔다. 이미 싼 값이 기준이라 같은 퍼센트라도 훨씬 넘기 어렵고,
그만큼 걸리면 신호가 강해서 알림 순위를 올려 준다.

40% 이상이면 🔥 대박으로 표시한다.

**갔을 때 날씨가 나쁘면 안 알린다.** Open-Meteo에서 최근 3년 실측 자료를 받아
목적지별·월별 평년값을 직접 계산한다. 우기·폭염·혹한기는 점수가 깎여 걸러진다.
설경이 목적인 곳(삿포로 등)은 추위 벌점을 절반만 준다.

**여행사 자유여행 특가도 같이 본다.** 웹투어·모두투어·온라인투어의 상품 목록을
읽어 같은 목적지·같은 일수 상품들과 비교한다.

## 시작하기

```bash
pip install -r requirements.txt
copy .env.example .env      # 값을 채운다
python main.py warmup       # 기후 자료를 미리 받아둔다 (한 번만, 몇 분 걸림)
python main.py test         # 텔레그램 연결 확인
python main.py loop         # 6시간마다 계속 돌린다
```

### 토큰 두 개

| 무엇 | 어디서 | 필수 |
|---|---|---|
| `TELEGRAM_BOT_TOKEN` | 텔레그램에서 `@BotFather` → `/newbot` | 알림 받으려면 필요 |
| `TRAVELPAYOUTS_TOKEN` | travelpayouts.com 무료 가입 → Flight Data API | 항공권 보려면 필요 |

`AMADEUS_CLIENT_ID` / `SECRET`은 선택이다. 넣으면 알림 보내기 직전에 실시간
가격으로 한 번 더 확인해서, 이미 팔린 가격을 거르고 보낸다.

**여행사 특가는 키가 하나도 없어도 된다.** `python main.py packages` 로 바로 확인할 수 있다.

### 알림 받을 사람 등록

`.env`의 `TELEGRAM_CHAT_ID`를 비워 두고 `python main.py listen` 을 켠 다음
봇에게 `/start` 를 보내면 자동 등록된다.

## 명령

| 명령 | 하는 일 |
|---|---|
| `python main.py scan` | 한 번 훑고 알림 발송 |
| `python main.py loop` | 정해진 시각에 계속 (기본 10:30, 22:30) |
| `python main.py packages` | 여행사 특가만 확인 (키 불필요) |
| `python main.py hours` | 새 최저가가 몇 시에 나왔는지 |
| `python main.py warmup` | 목적지 기후 자료 미리 받기 |
| `python main.py listen` | 텔레그램 명령 수신 |
| `python main.py status` | 설정과 수집 현황 |
| `python main.py test` | 텔레그램 연결 확인 |

봇에게 보낼 수 있는 명령: `/start` `/stop` `/status` `/now`

## 왜 하루 두 번, 왜 그 시각인가

**여행사는 영업시간이 있다.** 하나투어 타임세일이 매주 월요일 오전 10시로 확인된다.
상품 등록은 업무 시작 후 오전 중에 몰린다. 그래서 **10:30**에 한 번 본다.

**항공권은 영업시간이 없다.** 항공사 동적 가격은 24시간 알고리즘으로 움직이고,
스카이스캐너 Drops도 매시간 갱신한다. 다만 "화요일 오후~수요일 새벽에 항공사가
남은 좌석에 프로모션 요금을 건다"는 통설이 있어 그 직전인 **22:30**에 한 번 본다.
밤 늦어도 사람이 바로 예약할 수 있는 시간대이기도 하다.

**이 두 시각은 출발점일 뿐 근거가 반쪽이다.** 오전 10:30은 확인된 사실에 기댄
것이지만 22:30은 통설이다. 그래서 봇이 직접 재도록 해 뒀다.

```bash
python main.py hours
```

노선별로 직전까지의 최저가를 깬 순간만 골라 그 시각을 세어 막대로 보여 준다.
2~3주 돌린 뒤 이걸 보고 `.env`의 `SCAN_TIMES`를 실제 데이터에 맞춰 고치면 된다.

## 알아 둘 것

**여행사 상시 할인 10%는 특가가 아니다.** 실측해 보니 웹투어 상품 대부분이
정가 대비 정확히 10% 할인으로 붙어 있다. 그래서 정가 대비 할인율만으로는
파격을 못 가린다. 같은 목적지·같은 일수 또래 상품과 비교하는 쪽이 진짜 신호다.

**여행 일수를 나눠서 비교한다.** 오사카 3일과 오사카 5일을 같이 놓으면
3일짜리가 무조건 싸 보인다. 제목에서 일수를 뽑아 3일 이하 / 4~5일 / 6~7일 /
8일 이상으로 나눈 뒤 같은 묶음 안에서만 비교한다.

**숙박 전용 상품은 뺀다.** `룸 ONLY` 처럼 항공이 빠진 상품을 에어텔과 비교하면
반값으로 보인다. 제목에서 걸러 낸다.

**한 달에 두 번씩 묻는다.** Travelpayouts는 '출발 달'과 '귀국 달'을 따로 받는데,
둘을 같은 달로 주면 달을 넘겨 돌아오는 일정이 결과에서 통째로 빠진다. 겹치지도
않아서 한 번만 물으면 그만큼을 영영 못 본다. 실측으로 방콕 9월은 26건 중 11건이
그랬고, 후쿠오카·방콕·다낭은 **최저가가 전부 달을 넘기는 일정**이었다.
그래서 매달 (같은 달 귀국)과 (다음 달 귀국)을 각각 묻고 합친다.

**공항 코드는 바뀐다.** 신공항이 열리면 옛 코드가 죽는다. 씨엠립은 `REP`→`SAI`
(2023년), 울란바토르는 `ULN`→`UBN`(2021년)으로 바뀌어 있었다. 이런 건 그 목적지만
조용히 빠지고 총계는 멀쩡해 보여서 알아채기 어렵다. 반년에 한 번쯤 돌려서 확인해라.

```bash
python _smoke_airports.py
```

**여행사 사이트는 개편이 잦다.** 어떤 여행사에서 상품을 0건 읽으면 조용히
넘어가지 않고 "구조 변경 의심" 경고를 텔레그램으로 보낸다. 그때 `packages.py`의
해당 파서를 고치면 된다.

**첫 실행에는 항공권 딜이 거의 안 나온다.** 평소 가격을 알아야 싼지 판단할 수
있는데, 노선당 관측이 8건은 쌓여야 비교를 시작한다. 며칠 돌리면 정확해진다.
여행사 특가는 또래 비교라서 첫 실행부터 작동한다.

**며칠씩 조용한 게 정상이다.** 파격가는 원래 드물다. 실제로 어느 날 자유여행 상품
164건을 훑어도 -25% 넘는 게 하나도 없었고(최대 -17.7%), 그게 맞는 동작이다.
살아 있는지 확인하려면 `/status`(마지막 스캔 시각)나 `python main.py packages`를 보면 된다.
후자는 기준에 못 미친 상위권까지 같이 찍어 준다.

**그래도 스캔은 자주 한다.** 훑는 주기(6시간)와 알리는 문턱(-25%)은 별개다.
파격가는 몇 시간이면 사라져서, 하루 한 번만 보면 이미 팔린 뒤에 발견하게 된다.

**알림이 너무 없으면** `.env`에서 `DEAL_DROP_PCT` / `PACKAGE_DROP_PCT`를 15~20으로
낮추거나 `MIN_WEATHER_SCORE`를 50으로 내려라. 너무 많으면 반대로 올리면 된다.
